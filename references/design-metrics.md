# Design metrics — 把"好看"拆成可检查的数字

Excalidraw 画布丑，通常不是审美问题，而是几个可测量的量没控制住：容器比例、行距、公式尺寸方差、留白、层级数。下面每条都给出阈值和检查方法。

来源：`excalidraw-diagram-skill` 的 27 项 quality checklist（设计方法论部分）+ 本库实战校准。方法论可借用，但它的渲染闭环（Playwright 截图 → 看图 → 改）在 Obsidian 插件这条链路上不成立，用 `scripts/inspect_canvas.mjs` 的数值审计替代。

---

## 1. 容器比例（最影响"专业感"的一项）

**指标：被容器包住的文本块 ÷ 文本块总数 ≤ 30%。**

- 表格型画布（每格一个框）天然 100%，这就是它显"PPT 模板"的原因
- 结构线派（trunk + drop line + 悬空文字）可以做到 0%
- 只有承载语义的容器才算数：警示框、决策菱形、需要被箭头连的节点
- 检查：`inspect_canvas.mjs` 输出里 `types.rectangle ÷ types.text`

参考值：第十讲 v10（表格派）矩形 ≈ 25 个 / 文本 ≈ 60 个；第十讲 styleB（结构派）3 / 55 ≈ 5%。

## 2. 公式尺寸方差

**指标：同一画布内公式图片的 `height` 标准差应接近 0；`width` 变异系数（σ/μ）≤ 0.45。**

- 短公式被拉成巨无霸 = 宽度写死
- 做法：高度固定（46–52），宽度按 TeX 长度估算后 clamp 到 `[110, 列宽]`
- 检查：`inspect_canvas.mjs` 的 `formula size` 行

## 3. 字号层级（只允许 4 级）

| 级别 | 字号 | 用途 |
| --- | --- | --- |
| Hero | 30–34 | 画布标题 |
| Section | 18–22 | 列头 / 分区标题 |
| Body | 15–16 | 行标签、正文 |
| Detail | 12–14 | 注释、脚注、hint |

出现第 5 级（比如 17 和 19 混用）就会显得零乱。标题不需要框——字号已经是分隔符。

## 4. 垂直节奏

**指标：同类元素的 y 间距一致，误差 0（不是 ±4，是 0）。**

- 行距由最长内容决定：`label 高(≈19) + 间隔(6) + 公式高(46) + 段间(37) = 108`
- 列内 3–4 行是甜点，5 行以上视线开始跳
- 检查：把 `elements` 里所有 y 排序，相邻差值的众数应该是同一个数

## 5. 留白与层级

- Hero 元素四周留白 ≥ 120 px（重要性靠空白表达）
- 画布外边距 ≥ 80 px，否则打开时内容贴边
- 两个分区之间的距离 ≈ 一个行距的 3 倍以上，否则"分区"读不出分区

## 6. 颜色：语义化，不装饰

- 每列一个色，颜色只在三处出现：列头文字、分支圆点、竖线。**不要给整列铺底色**
- 一屏不超过 5 个语义色；第 6 个开始就变成彩虹
- 色板取现成的（用户已有画布 / `references/theme-and-color.md`），不要临场调色
- 警示色只用于警示。把红色用在"侧面积列头"又用在"错误提示"，语义就冲突了

## 7. 线条承担结构

- 主干线（trunk）+ 垂直落线（drop）比"列框 + 行分隔线"更轻，且拖动能整列跟随
- `strokeWidth` 只用 1 / 2 / 3 三档：1 分隔线，2 结构线，3 强调主轴
- 虚线的含义固定为"从属 / 待定"（如形心列从属于左侧四列、待解问题区）
- 圆点（`ellipse` 直径 14–18）当锚点：比小方块自然，比箭头省地方

## 8. `roughness` / `opacity`

- `roughness: 0`（本库全部笔记都是 0，手绘感会破坏公式可读性）
- `opacity: 100` 恒定。**不要用透明度做层级**——用字号和颜色。半透明元素在深色主题切换时会发灰

## 两种版式（按内容选，不要混）

| | 表格派（column grid） | 结构派（lines as structure） |
| --- | --- | --- |
| 适合 | 量大、条目同级、需要逐格核对 | 有分支判断、要表达"从属/合成"关系 |
| 结构 | 列框 + 行分隔线 | 主干线 + 落线 + 悬空文字 |
| 容器比例 | 高（每列一个框） | 接近 0 |
| 观感 | 严谨、像速查表 | 轻、像讲义板书 |
| 风险 | 容易被说"丑/像模板" | 分支多时线会打结 |
| 本库示例 | `10-积分几何应用.excalidraw.md` | `10-积分几何应用2.excalidraw.md` |

判断口诀：**列之间是"并列同类"→ 表格派；列之间有"派生/依赖"→ 结构派。**

## 没有渲染器时怎么验收

插件这条链路上截不了图，用三层替代检查，顺序执行：

1. **结构审计**：`node scripts/inspect_canvas.mjs <file>` —— 公式数 = 图片数、无悬空绑定、字号集合、roughness 集合、边界尺寸。
2. **重叠检测**：遍历 `text | image | rectangle` 的包围盒，成对求交，面积 > 4×4 px 即报。允许的例外只有"文字落在容器内"这一类（警示框）。
3. **边界检测**：`max(x+w)`、`max(y+h)` 应等于设计稿的右下角，多出 50 px 以上说明有元素飘出去了。

三层都过还不等于好看——真正的判断仍然是用户打开看一眼。所以生成时**宁可留白过多，不要留白不足**：挤是硬伤，空是可以后续补内容的。
